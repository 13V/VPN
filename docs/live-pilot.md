# Velora private live VPN pilot — 2026-09-23

The repository now supports a **gated real WireGuard pilot** alongside the existing sample portal. It uses a prepaid VPNresellers reseller account. An operator provisions at most one account by default, fixes its expiry, verifies that its configuration can be retrieved, then gives a wallet-bound access code to the intended tester. The signed-in tester checks the code and downloads the current `.conf` file through the portal. The download is retrieved again from the supplier on demand; no supplier private key or configuration is stored in Git or Vercel Blob.

This is an operator-funded pilot, **not** token-funded holder access. Creating a reseller account starts supplier billing. The code does not create a token, calculate holder eligibility, claim Pons fees, convert those fees into supplier credit or assert that a WireGuard connection works. No real account can be provisioned until a reseller account, API token and prepaid credit exist. Production remains in demo mode until the pilot credentials are configured.

## Why this supplier path

VPNresellers explicitly offers reseller access, [crypto top-ups](https://www.vpnresellers.com/help/getting-started/what-countries-can-resell), a [prepaid balance with daily active-account billing](https://www.vpnresellers.com/help/pricing/pricing-of-vpnresellers), and an API to [create accounts and repeatedly retrieve WireGuard configurations](https://api.vpnresellers.com/docs/v4_1/). The published minimum top-up is **$25** and the published standard rate is **$1.99/month per active account**, billed daily; recheck the actual offer before funding. These are supplier statements, not observed paid results. The repeatable GET is a promising recovery mechanism, but it still needs a paid test. Obtain the actual current reseller terms and perform a tunnel, DNS and throughput check before widening access.

## Operator setup

1. Create a VPNresellers account and add the minimum prepaid credit using its offered crypto method. Obtain an API token from its dashboard. Keep the token in the local operator environment; never commit it or paste it into chat.
2. Generate a random 32-byte signing secret as 64 hexadecimal characters. Store the **same** `VPN_PILOT_SIGNING_KEY` in the operator environment and Vercel Production. This secret signs wallet-bound pilot codes. Keep it outside Git and cloud-synced folders.
3. Set `VPN_RESELLERS_API_TOKEN` and a private `VPN_PILOT_STATE_DIR` outside this checkout. Set `VPN_PILOT_MAX_ACCOUNTS=1` for the first test. The pilot journal records a supplier account password only while account creation is unresolved. Restrict filesystem access to the operator. On Windows, verify the directory ACL.
4. Run `npm ci`, `npm test`, then `npm run pilot:preflight`. Confirm the reported balance and Australia server ID. The preflight makes only read calls.
5. Using a wallet controlled by the tester, run `npm run pilot -- provision 0xWALLET --live`. This creates **one** supplier account, sets a fixed expiry at the UTC midnight following at least one full day, then retrieves and validates a configuration. It records a create intent before calling the supplier. The command never prints the password or configuration.
6. If interrupted or unresolved, run `npm run pilot -- resume 0xWALLET`. It searches for the deterministic supplier username before any create retry. A missing search result remains unresolved; it does **not** create a replacement account. Inspect the reseller dashboard to resolve that case. Repeated configuration GETs never create another account.
7. Once the report says `ready`, run `npm run pilot -- grant 0xWALLET`. It writes a wallet-bound access code to a private file under `VPN_PILOT_STATE_DIR` and prints only that path. Give the code to the tester through a private channel that you control. The code expires with the account and does not authorize another wallet.
8. Set `VPN_RESELLERS_API_TOKEN`, `VPN_PILOT_SIGNING_KEY` and `VPN_PILOT_ENABLED=1` as **server-side Production** Vercel variables and redeploy. Do not set them with a `NEXT_PUBLIC_` prefix. The portal's `/api/bootstrap` then exposes only `pilotEnabled: true`, never the credentials. The demo remains available for other visitors.
9. Tester signs into the portal with the approved wallet on Robinhood Chain, enters the code, checks status, and downloads `velora-pilot.conf`. Import it into the official WireGuard app and activate it. Independently check handshake, public exit IP, DNS resolution/leaks, throughput, renewal/expiry and the supplier's actual account status. Until those checks pass, do not advertise general live access.

To stop the pilot, run `npm run pilot -- disable 0xWALLET --live`, then confirm `Disabled` in the supplier dashboard. An ambiguous disable response is marked unresolved; check the dashboard, because the account could still incur daily charges. Set `VPN_PILOT_ENABLED=0`, remove the production API token and signing key when the pilot ends, then redeploy. Rotating the signing key invalidates all outstanding codes.

## Safety and limits

- The operator defaults to **one** pilot account and accepts no more than three even if explicitly configured. It requires at least $2 of visible prepaid credit before creating an account. This is a gate, not a hard monetary cap: the supplier controls daily debits, and account creation may have side effects before an expiry response is confirmed.
- A fixed expiry is required before a code can be issued. A lost create or expiry response is reconciled with read endpoints, never by blindly repeating account creation. An account that cannot be found after an uncertain create stays unresolved.
- Every configuration download checks the signed wallet and supplier account status/expiry, then performs a repeatable GET. The API route returns `Cache-Control: no-store`; the browser keeps the code only in tab session storage. A downloaded config remains usable if shared, so tester handling and supplier revocation matter.
- Supplier-provided WireGuard private keys and configurations are processed in memory and returned only to the authenticated, approved wallet session. A restricted worker and dedicated transactional database are needed before broader self-service release. The Vercel secret is still powerful; keep the pilot small, monitor API usage and remove it after testing.
- Existing nadanada/Blink validation remains independent and blocked. Token funding and public holder eligibility still require their own evidence and operational controls.
